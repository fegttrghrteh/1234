# Операторы сравнения, логические операторы и условные конструкции

В этом блоке мы переходим от обычных вычислений к решениям, в которых программа должна **сравнивать значения и выбирать дальнейшее действие**.

До этого выражение почти всегда давало число или строку. Теперь нас будет интересовать ещё один тип результата — `boolean`: `true` или `false`.

---

## 1. Операторы сравнения

Операторы сравнения отвечают на вопрос о двух значениях и возвращают `true` или `false`.

| Оператор | Значение |
|---|---|
| `>` | больше |
| `<` | меньше |
| `>=` | больше или равно |
| `<=` | меньше или равно |
| `==` | нестрогое равенство |
| `!=` | нестрогое неравенство |
| `===` | строгое равенство |
| `!==` | строгое неравенство |

```js
const a = 5;
const b = 8;

console.log(a < b);   // true
console.log(a > b);   // false
console.log(a <= 5);  // true
console.log(b >= 10); // false
```

### Строгое и нестрогое равенство

`==` перед сравнением может привести значения к совместимым типам. `===` сравнивает и значение, и тип.

```js
console.log(5 == '5');   // true
console.log(5 === '5');  // false

console.log(0 == false);   // true
console.log(0 === false);  // false
```

В учебных задачах лучше по умолчанию использовать `===` и `!==`. Так меньше скрытых преобразований и проще понимать код.

---

## 2. Сравнение строк

Если сравниваются две строки, JavaScript сравнивает их посимвольно.

```js
console.log('9' < '10');  // false
console.log('09' < '10'); // true
```

Это не числовое сравнение. Если строки должны интерпретироваться как числа, сначала преобразуйте их:

```js
console.log(Number('9') < Number('10')); // true
```

## 3. `NaN`, `null` и `undefined` в сравнениях

`NaN` означает специальное числовое значение «не число». Оно появляется, когда числовое преобразование или вычисление не даёт корректного числа.

```js
const value = Number('12px');

console.log(value);          // NaN
console.log(typeof value);   // 'number'
console.log(value === NaN);  // false
console.log(Number.isNaN(value)); // true
```

Важная особенность: `NaN` не равно даже самому себе.

```js
console.log(NaN === NaN); // false
```

Для явной проверки предпочтительно использовать `Number.isNaN(...)`.

`undefined` обычно означает, что значение ещё не было задано. `null` — явное отсутствие значения.

```js
let first;
const second = null;

console.log(first);  // undefined
console.log(second); // null
```

Историческая особенность языка:

```js
console.log(typeof undefined); // 'undefined'
console.log(typeof null);      // 'object'
```

## 4. Truthy и falsy

В условии JavaScript может использовать не только `true` и `false`. Другие значения автоматически приводятся к логическому типу.

К основным **falsy**-значениям относятся:

```text
false
0
-0
0n
''
null
undefined
NaN
```

Почти все остальные значения являются **truthy**, в том числе строка с пробелом, пустой массив и пустой объект.

```js
console.log(Boolean(0));      // false
console.log(Boolean(''));     // false
console.log(Boolean(' '));    // true
console.log(Boolean(-5));     // true
console.log(Boolean([]));     // true
console.log(Boolean({}));     // true
```

Двойное отрицание часто используют как короткое преобразование к `boolean`:

```js
const value = 'JavaScript';
console.log(!!value); // true
```

## 5. Логические операторы

### Логическое И — `&&`

Результат условия будет истинным, если обе части истинны.

```js
const age = 20;
const hasTicket = true;

console.log(age >= 18 && hasTicket); // true
```

### Логическое ИЛИ — `||`

Достаточно, чтобы хотя бы одна часть была истинной.

```js
const isAdmin = false;
const isModerator = true;

console.log(isAdmin || isModerator); // true
```

### Логическое НЕ — `!`

Инвертирует логическое значение.

```js
const isBlocked = false;
console.log(!isBlocked); // true
```

У операторов `&&` и `||` есть короткое замыкание: JavaScript прекращает вычисление, когда результат уже понятен.

```js
const username = '';
const visibleName = username || 'Гость';

console.log(visibleName); // 'Гость'
```

Важно помнить: `&&` и `||` возвращают не обязательно `boolean`, а один из операндов.

## 6. Условная конструкция `if`

Самая простая форма:

```js
const temperature = 25;

if (temperature > 20) {
  console.log('Тепло');
}
```

Если нужно два варианта:

```js
const age = 17;

if (age >= 18) {
  console.log('Доступ разрешён');
} else {
  console.log('Доступ запрещён');
}
```

Для нескольких диапазонов используется `else if`:

```js
const score = 82;

if (score >= 90) {
  console.log('5');
} else if (score >= 75) {
  console.log('4');
} else if (score >= 60) {
  console.log('3');
} else {
  console.log('2');
}
```

Порядок проверок важен. После первого подходящего условия остальные ветки этой цепочки уже не выполняются.

---

## 7. Несколько условий одновременно

Диапазон в JavaScript записывается через две проверки:

```js
const value = 7;

if (value > 0 && value < 10) {
  console.log('Число находится между 0 и 10');
}
```

Запись из математики использовать нельзя:

```js
0 < value < 10
```

JavaScript сначала вычислит `0 < value`, получит `true` или `false`, а затем будет сравнивать уже это логическое значение с `10`. Поэтому результат может оказаться неожиданным.

---

## 8. Вложенные условия

`if` можно помещать внутрь другого `if`:

```js
const age = 20;
const hasTicket = true;

if (age >= 18) {
  if (hasTicket) {
    console.log('Проходите');
  } else {
    console.log('Нужен билет');
  }
} else {
  console.log('Недостаточный возраст');
}
```

Если вложенность становится слишком большой, код обычно проще переписать через логические операторы или изменить порядок проверок.

---

## 9. Тернарный оператор

Тернарный оператор удобен для короткого выбора одного из двух значений:

```js
const age = 20;
const status = age >= 18 ? 'Совершеннолетний' : 'Несовершеннолетний';

console.log(status);
```

Общий вид:

```js
условие ? значение_если_true : значение_если_false
```

Вложенные тернарные операторы допустимы, но быстро ухудшают читаемость. Для нескольких веток чаще лучше `if / else if / else`.

---

## 10. Nullish coalescing — `??`

Оператор `??` подставляет значение справа только тогда, когда слева находится `null` или `undefined`.

```js
const name = null;
console.log(name ?? 'Гость'); // 'Гость'
```

Он отличается от `||`:

```js
console.log(0 || 100);  // 100
console.log(0 ?? 100);  // 0

console.log('' || 'empty'); // 'empty'
console.log('' ?? 'empty'); // ''
```

Поэтому `??` удобен, когда `0`, `false` или пустая строка являются допустимыми значениями и их не нужно заменять.

## 11. `switch`

`switch` удобен, когда одно выражение нужно сравнить с несколькими конкретными вариантами.

```js
const day = 2;

switch (day) {
  case 1:
    console.log('Понедельник');
    break;
  case 2:
    console.log('Вторник');
    break;
  default:
    console.log('Неизвестный день');
}
```

Сравнение `case` по смыслу соответствует строгому равенству.

```js
const value = 5;

switch (value) {
  case '5':
    console.log('Строка');
    break;
  case 5:
    console.log('Число');
    break;
}
```

### Несколько `case` для одного результата

```js
const day = 6;

switch (day) {
  case 1:
  case 2:
  case 3:
  case 4:
  case 5:
    console.log('Рабочий день');
    break;
  case 6:
  case 7:
    console.log('Выходной');
    break;
  default:
    console.log('Некорректный номер дня');
}
```

Если забыть `break`, выполнение продолжится в следующем `case`. Иногда это используют специально, но чаще это источник ошибки.

---

## 12. `switch (true)` для диапазонов

Обычный `switch (value)` лучше подходит для конкретных значений. Для диапазонов привычнее `if / else if`.

Иногда встречается приём `switch (true)`:

```js
const total = 6500;

switch (true) {
  case total >= 10000:
    console.log('Скидка 10%');
    break;
  case total >= 5000:
    console.log('Скидка 5%');
    break;
  case total >= 1000:
    console.log('Скидка 1%');
    break;
  default:
    console.log('Без скидки');
}
```

Такой код работает, потому что каждое выражение после `case` вычисляется в `true` или `false`. На начальном уровне для диапазонов обычно проще читать `if / else if`.

---

## 13. Частые ошибки

### 1. Использовать `==`, когда нет причины для преобразования типов

```js
5 == '5'   // true
5 === '5'  // false
```

### 2. Проверять `NaN` через равенство

```js
value === NaN // всегда false
Number.isNaN(value) // корректная проверка
```

### 3. Записывать диапазон как в математике

```js
0 < value < 10 // не то, что ожидается
value > 0 && value < 10 // корректно
```

### 4. Забывать `break` в `switch`

Если `break` отсутствует, программа перейдёт к следующему `case`.

### 5. Путать `||` и `??`

`||` реагирует на любое falsy-значение, а `??` — только на `null` и `undefined`.

---

## Короткий итог

После этой темы важно уметь:

- сравнивать значения;
- отличать `===` от `==`;
- объединять проверки через `&&`, `||`, `!`;
- записывать диапазоны;
- строить ветвление через `if / else if / else`;
- использовать тернарный оператор для короткого выбора;
- понимать назначение `??`;
- использовать `switch` для нескольких фиксированных вариантов.
